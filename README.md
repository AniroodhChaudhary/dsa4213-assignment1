# DSA4213 Assignment 1 — Language models, embeddings and representations

Code and results for a three-part study on WikiText-2 and AG News:

* **Part I** — n-gram (interpolated Kneser-Ney), vanilla RNN, LSTM and Transformer
  next-token language models trained on the same corpus and compared on test
  perplexity, cost, learning curves and generated text.
* **Part II** — LSTM with three input-embedding settings (random trainable,
  own skip-gram frozen, public GloVe frozen), extended to a 3 × 2
  source × trainability factorial.
* **Part III** — frozen LM representations (and embedding-only / TF-IDF baselines)
  as features for AG News topic classification with one logistic-regression classifier.

The framing question: *does better next-token prediction translate into better
frozen representations for classification, and how much do embedding choices matter?*

## Data access

| Dataset | Source | Splits used |
|---|---|---|
| WikiText-2 (Merity et al., 2016) | Hugging Face `Salesforce/wikitext`, config `wikitext-2-v1` | train / validation / test |
| AG News (Zhang et al., 2015) | Hugging Face `fancyzhx/ag_news` | train (20k+2k stratified subset) / test (7,600) |
| GloVe 6B 300d (Pennington et al., 2014) | https://nlp.stanford.edu/data/glove.6B.zip | 300d table |

`scripts/prepare_data.py` downloads both datasets through `datasets` (parquet, no
custom loading script) and `scripts/download_glove.sh` fetches GloVe (822 MB zip).
Nothing else is needed; no credentials.

## Preprocessing decisions

* WikiText-2 is used in its pre-tokenised form (`<unk>` already present). Empty lines
  are dropped, headings are kept, **all text is lowercased once**, and one `<eos>` is
  appended to every line. Lowercasing is required so that the *uncased* GloVe-6B
  table in Part II does not receive an unfair advantage (`The`/`the` sharing one
  vector only in that setting). It shrinks the vocabulary from 33,278 to **28,913**
  types, so perplexities are not comparable with published WikiText-2 numbers.
* The vocabulary is built from the train split only; validation and test have no
  out-of-vocabulary tokens beyond the dataset's own `<unk>` (verified in
  `results/data/coverage.json`). `<pad>` is the last id and appears only in the
  padded AG News batches of Part III, never in language-model training.
* LM training and evaluation use one continuous token stream per split
  (train 2,075,678 tokens; validation 216,348; test 244,103). No padding enters any
  LM loss. Every model is scored on exactly the same 244,102 test targets.
* AG News text is tokenised with sacremoses plus WikiText's `@-@`, `@,@`, `@.@`
  conventions, lowercased, mapped onto the WikiText vocabulary (92.5% of tokens in
  vocabulary, the rest `<unk>`), prefixed with `<eos>` and truncated to 96 tokens
  (under 1% of documents truncated).

|---|---|---|---|---|
| Kneser-Ney 5-gram | 214.9 | – | 5.8 M entries | 0.1 |
| tanh RNN, 2×300 | 173.0 | 177.2 | 17.7 M (0.36 M) | 23.2 |

Convergence check (same configs, 24-epoch cap): the LSTM early-stops with best validation at epoch 18
(test PPL 124.6, context-reset 141.0); the Transformer is still improving at epoch 24 (test PPL 132.3,
context-reset 137.3). The full-history ranking (LSTM < Transformer) and the context-reset ranking
(Transformer < LSTM) both survive the doubled budget.

Part II, the LSTM with six input-embedding settings (test PPL; ± half the range over seeds 0 and 1):

| Source \ trainability | frozen | trainable |
|---|---|---|
| random U(−0.1, 0.1) | 198.0 | 134.0 ± 0.3 |
| own skip-gram (1.9 min CPU) | 127.9 ± 0.5 | 119.0 |
| GloVe 6B 300d | 123.8 ± 0.4 | 116.5 |

Part III, AG News macro-F1 (%) of one logistic regression on frozen representations (20k labels):
LSTM last state 62.3, LSTM mean 67.9, Transformer mean 77.6, RNN mean 73.5, 1-layer Transformer mean
78.9, LSTM+frozen skip-gram mean 79.3, LSTM+frozen GloVe mean 82.3; embedding-only means: learned
table 75.1, skip-gram 83.4, GloVe 87.9; TF-IDF 89.9. Spearman correlation between source-LM
perplexity and downstream F1 over the six LM-based representations: −0.60. Better next-token
prediction did not give better frozen representations on this data.

## Environment

Apple M4 (10-core), 16 GB unified memory, macOS 15, PyTorch 2.14 with the MPS
backend, Python 3.11 managed by [uv](https://docs.astral.sh/uv/). Everything in
`results/` was produced on this machine; run times in the report refer to it.

The report is compiled with [tectonic](https://tectonic-typesetting.github.io) (`brew install
tectonic`; `report/build.sh`), which is only needed to rebuild the PDF.

```bash
uv sync            # creates .venv from pyproject.toml + uv.lock
uv run pytest -q   # 9 tests: causality, no weight tying, KN normalisation, pooling, scoring
```

## Reproducing the results

`run_all.sh` lists every command in order (about 7 h on the M4 including the optional
24-epoch convergence runs; about 5 h without them). The main steps:

```bash
bash scripts/download_glove.sh
uv run scripts/prepare_data.py
uv run scripts/train_ngram.py                                     # Part I n-gram (orders 2–5, selected on validation)
uv run scripts/train_lm.py --config configs/lstm.yaml [--seed 1]  # any neural run; see configs/
uv run scripts/train_word2vec.py && uv run scripts/build_embedding_matrix.py
uv run scripts/evaluate_lm.py --run lstm_s0      # test perplexity, inference workload, generations
uv run scripts/extract_features.py && uv run scripts/train_classifier.py
uv run scripts/make_report_assets.py && bash report/build.sh
```

Configuration lives in `configs/`: `common.yaml` holds the shared recipe (embedding
dim 300, batch 32 × bptt 128, Adam 1e-3 with 200-step warm-up, halve the LR after two
consecutive epochs without validation improvement, early stop after three, gradient clip 1.0,
dropout 0.3, max 12 epochs); each run config overrides only the model / embedding
block. Run names are `<config>_s<seed>`.

**Seeds.** Everything uses seed 0 (Part II's required settings are repeated with
seed 1). Data subsets, prompts, embedding initialisation and decoding are all
seeded. Training on MPS is *not* bit-reproducible (the embedding backward uses
non-deterministic scatter kernels); the seed-0/seed-1 pairs of Part II differ by 0.5 to
1.1 test-perplexity points, and a same-seed repeat (the first 12 epochs of the 24-epoch runs)
differs by under 0.05. `--device cpu` gives exact reproduction at a large speed cost.

## Use of external code, data and tools

* Datasets and embeddings as cited above; PyTorch, gensim, scikit-learn, sacremoses,
  Hugging Face `datasets`.
* The training loop follows the structure of the PyTorch `word_language_model`
  example (continuous-stream batching, detached hidden state); the Kneser-Ney
  implementation follows Chen & Goodman (1998).
* **AI assistance.** Claude Code (Anthropic, model Claude Fable 5.1) was used as a
  coding assistant to draft the experiment design, the code in this repository, the
  scripts that turn results into tables and figures, and to edit the report text.
  All experiments were run by the author on the hardware above; the analysis and
  interpretation in the report were reviewed and are the author's own. Details in
  `AI_USAGE.md`.
