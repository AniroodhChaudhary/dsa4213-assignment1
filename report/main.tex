\section{Question and setup}
Two things are commonly assumed about small language models (LMs): that lower perplexity means a better model, and that better LMs give better text representations. This report tests both on one corpus. The question is: \emph{does better next-token prediction translate into better frozen representations for topic classification, and how much do input-embedding choices matter?} Part~I trains four LM families on WikiText-2 under one recipe; Part~II keeps the LSTM (the best full-history model of Part~I and the cheapest per epoch) and varies only its input table in a $3\times2$ (source $\times$ trainability) design; Part~III feeds the frozen models' states to one linear classifier on AG News. Everything not under study (vocabulary, stream, embedding width, output layer, optimiser, schedule, evaluation, prompts, decoding, classifier) is held fixed.

\section{Data and common protocol}
\paragraph{Corpus and vocabulary.} WikiText-2 \citep{merity2017pointer} (pre-tokenised, with its own \texttt{<unk>}) is lowercased once, one \texttt{<eos>} is appended per line, and the vocabulary is built from the train split only: \nVocab{} types. Lowercasing is a fairness decision: GloVe-6B is uncased, so a cased vocabulary would let \emph{The}/\emph{the} share one vector only in Part~II's GloVe setting; it shrinks the vocabulary from 33,278 types, so perplexities are not comparable with published numbers. Validation and test contain no out-of-vocabulary tokens beyond the dataset's own \texttt{<unk>} (\unkFracTest\% of test tokens), which every model, including the $n$-gram, treats as an ordinary vocabulary item.

\paragraph{Streams and perplexity.} Each split is one continuous token stream (train \nTrainTok{} tokens, validation \nValTok); no padding exists, so nothing has to be excluded from any loss, and every model is scored on the same \nTestTargets{} test targets, perplexity being $\exp$ of the mean per-target cross-entropy. Recurrent models are scored with batch~1 and the state carried over the entire stream (full history); the Transformer with a sliding 128-token window moved by 32, scoring the last 32 targets of each window (the first window scores all 128; every later target sees $\ge$96 tokens of context). A second protocol, non-overlapping 128-token blocks with the state reset, is identical for every model and isolates context length. Validation during training uses the same protocols, so curves and final numbers are comparable.

\paragraph{Models and recipe.} All neural models share a $300$-d input embedding (the largest width GloVe-6B ships, so Part~II can reuse it) initialised $\mathcal{U}(-0.1,0.1)$ and a $300\!\times\!V$ output layer, so they differ only in the sequence core: a 2-layer tanh RNN (0.36\,M core parameters), a 2-layer LSTM \citep{hochreiter1997long} (1.44\,M), a 4-layer pre-LN Transformer \citep{vaswani2017attention} with 6 heads and FFN width 1200 (4.37\,M) and, as a parameter-count control, the same Transformer with 1 layer (\coreMTransformerOne\,M). The $n$-gram baseline is interpolated Kneser--Ney \citep{kneser1995improved,chen1998empirical} with one discount per order, orders 2--5 fitted and the order chosen on validation. The neural recipe is identical for every run (hyper-parameters in Appendix~C): batch 32 $\times$ 128-token BPTT chunks with the state detached between chunks, dropout 0.3 (the Transformer additionally drops attention and FFN activations at 0.3), Adam ($10^{-3}$, 200-step warm-up), learning rate halved after two consecutive epochs without validation improvement, early stopping after three, at most 12 epochs, global gradient clipping at 1.0 with the pre-clip norm logged at every step. A unit test perturbs future tokens and checks that no model's earlier logits change (causality) and that input and output tables are not tied.

\paragraph{Cost measurement.}
All runs use one Apple M4 (16\,GB) through PyTorch~2.14's MPS backend \citep{paszke2019pytorch}, one process at a time. Timers synchronise the device before and after each measurement; epoch~1 includes shader compilation and is excluded from per-epoch averages. Model size is the parameter count and the saved fp32
checkpoint. The common inference workload is (A)~scoring the full test stream with the protocol
above and (B)~generating 50 tokens for each of 5 prompts at batch~1 with top-$k$ sampling (the
Transformer without a KV cache). MPS is not bit-deterministic: the 24-epoch runs repeat the first 12 epochs of the seed-0 runs and differ from them by \mpsRepeatDiffLSTM{} (LSTM) and \mpsRepeatDiffTransformer{} (Transformer) validation PPL at epoch 12, so run-to-run noise is negligible; the seed-1 repeats in Part~II measure seed variance instead (about one point), and \texttt{--device cpu} reproduces exactly.

\paragraph{Generation.} Five prompts are the first 10 tokens of seeded-random \emph{validation} lines ($\ge$30 tokens, not headings, no \texttt{<unk>} in the prompt; never test); every model continues each for 50 tokens with greedy decoding and with top-$k$=40, $T$=1 sampling from one shared CPU sampler, so decoding is matched exactly across the $n$-gram and neural models. Continuations are summarised by distinct-$n$ ratios and the fraction of 4-grams repeating an earlier 4-gram of the same continuation.

\paragraph{Observations.}
\emph{Prediction quality} (Table~\ref{tab:p1q}). With full history the order is LSTM (\pplLSTM) $<$
Transformer (\pplTransformer) $<$ RNN (\pplRNN) $\approx$ 1-layer Transformer (\pplTransformerOne) $<$
KN 5-gram (\pplNgram). Under the matched protocol (context reset every 128 tokens for every model; the common evaluation setup, since full-history scoring favours the recurrent models) the order of the two best models \emph{reverses}: the Transformer loses only \deltaBlocksTransformer{} points, the LSTM loses \deltaBlocksLSTM{} and ends up behind it.
\emph{Learning behaviour} (Fig.~\ref{fig:p1curves}). All four neural models were still improving at the 12-epoch cap: no learning-rate halving or early stop fired, and the train/validation gap grows (LSTM: \trainPplLastLSTM{} with dropout on vs.\ \valPplLastLSTM{} at epoch 12) without the validation loss turning up, i.e.\ no overfitting at this budget. Per epoch the LSTM and 4-layer Transformer track each other; per wall-clock minute the LSTM leads the Transformer (epochs of \epochSecLSTM{} vs.\ \epochSecTransformer{}\,s). After three epochs the tanh RNN is the \emph{best} model (\valEpThreeRNN{} vs.\ \valEpThreeLSTM{} and \valEpThreeTransformer); it learns fastest and saturates first.
\emph{Where the differences sit} (Fig.~\ref{fig:p1buckets}). On the \fracRare\% of test targets seen at most 10 times in training the $n$-gram is the best model (\ceRareNgram{} nats vs.\ \ceRareLSTM{} for the LSTM); every neural model wins on words seen $\ge$11 times, up to the most frequent bucket (\textgreater10k: LSTM \ceTopLSTM{} vs.\ $n$-gram \ceTopNgram). The Transformer is the best model on \texttt{<eos>} (\ceEosTransformer{} vs.\ \ceEosLSTM) but worse than the LSTM on \texttt{<unk>} (\ceUnkTransformer{} vs.\ \ceUnkLSTM).
\emph{Cost} (Table~\ref{tab:p1c}). The 4-layer Transformer needs \trainMinTransformer{}\,min of training
against \trainMinLSTM{} for the LSTM and reaches a worse full-history perplexity with 3$\times$ the core
parameters. On the common inference workload (scoring the test stream in 128-token blocks, 16 per batch) the models reach \scoreBlocksTokSRNN{} (RNN), \scoreBlocksTokSLSTM{} (LSTM), \scoreBlocksTokSTransformer{} (4L) and \scoreBlocksTokSTransformerOne{} (1L) tokens/s; under their own protocols the batch-1 recurrent models fall to \scoreTokSRNN{} and \scoreTokSLSTM{} and the sliding window costs the Transformer \scoreTokSTransformer. Sampling costs \genMsLSTM{} (LSTM) vs.\ \genMsTransformer{}\,ms per token (Transformer, no KV cache). The $n$-gram fits and validates all four orders in \ngramSelectSec{}\,s and scores at \scoreTokSNgram{} tokens/s on the CPU, but in this dictionary implementation its 156\,MB of tables exceed any checkpoint and sampling its full distribution costs \genMsNgram{}\,ms per token.
\emph{Generated text} (Table~\ref{tab:p1gen}, Appendix~A). Under greedy decoding the RNN and 1-layer Transformer loop (\repGreedyRNN\% and \repGreedyTransformerOne\% of 4-grams repeat an earlier one; $n$-gram \repGreedyNgram\%), the LSTM and 4-layer Transformer far less (\repGreedyLSTM\%, \repGreedyTransformer\%). Top-$k$ sampling removes repetition for every model ($\le$\repTopkTransformerOne\%), so sampled continuations differ in local fluency and consistency instead: the LSTM and Transformer hold a topic across the 50 tokens (a ``route description'' section after the highway prompt, the Ming court after the 1644 prompt), the RNN drifts within a sentence and the $n$-gram within a few tokens.

\paragraph{Explanations, separated from the observations.}
\emph{The LSTM's lead is a context-length effect.} Under context reset the Transformer is the better predictor, so the LSTM's full-history lead comes from information carried beyond 128 tokens (WikiText articles are thousands of tokens long); whether a longer-window Transformer would close the gap was not tested, and carrying state indefinitely is itself an architectural property. \emph{Parameter count does not explain the ranking.} The 1-layer Transformer has about the
LSTM's core size (\coreMTransformerOne{}M vs.\ \coreMLSTM{}M) and is \deltaOneLayerVsLSTM{} points
worse, while the 4-layer model has 3$\times$ the LSTM's core and is still worse with full history; depth
matters for the Transformer, but more parameters did not buy a better model at this budget.
\emph{Training budget conditions every conclusion.} Nothing converged in 12 epochs and the ranking at
epoch~3 (RNN first) differs from that at epoch~12, so we re-ran the LSTM and Transformer for 24
epochs (last column of Table~\ref{tab:p1q}, dashed in Fig.~\ref{fig:p1curves}): the LSTM early-stopped
with its best validation at epoch \bestEpochLongLSTM{} (test PPL \pplLongLSTM), the Transformer was still
improving at epoch 24 (\pplLongTransformer), and under context reset the Transformer still leads
(\pplLongBlocksTransformer{} vs.\ \pplLongBlocksLSTM), so both conclusions survive a doubled budget. \emph{The $n$-gram's edge on rare words} is
expected from Kneser--Ney's continuation counts, which model how many contexts a rare type appears in,
whereas an embedding row updated at most ten times has barely moved from its initialisation
(a hypothesis; Part~II tests its input side with pre-trained rows, while the equally under-trained output rows stay untested). \emph{The RNN's slow batch-1 scoring} is a kernel effect, not an architectural one: batched in 128-token blocks it reaches \scoreBlocksTokSRNN{} tokens/s. \emph{Greedy loops} track model quality (\repGreedyRNN\% and \repGreedyTransformerOne\% vs.\ \repGreedyLSTM\% and \repGreedyTransformer\%) under one identical decoder, so they reflect weaker modelling of the recent context rather than the decoding rule.

\paragraph{Design.}
The LSTM of Part~I is retrained with its $300$-d input table replaced by (b) skip-gram vectors \citep{mikolov2013distributed} trained
by us on the WikiText-2 train stream only (gensim \citep{rehurek2010gensim}, negative sampling; \skipgramMinutes{}\,min on the CPU,
reported separately from LM training) and (c) public GloVe-6B vectors \citep{pennington2014glove}, both
kept entirely frozen; (a) is the Part~I model itself. Because the required three cells confound
\emph{trainability} with \emph{information content}, three cheap extra cells complete a $3\times2$
factorial: the same two pre-trained tables left trainable, and a frozen random table (no information at
all). Skip-gram covers every type that occurs in the stream (\texttt{min\_count}=1; only \texttt{<pad>} is missing). GloVe covers \gloveCoverageTypes\% of the types and \gloveCoverageTokens\% of train tokens; the \gloveMissing{} missing types include the most frequent tokens of all (\texttt{\gloveMissingExamples}) and are initialised $\mathcal{N}(0,\sigma_d)$ with $\sigma_d$ the per-dimension standard deviation of the found rows (a frozen zero row for \texttt{<eos>} would cripple the model). The tables differ in scale (mean row norm \rowNormGloveTable{} GloVe, \rowNormSkipgramTable{} skip-gram, 1.0 random; nothing is rescaled, a disclosed confound). Freezing is verified by hashing the table before and after training; the required cells are run with seeds 0 and 1.

\paragraph{Observations.}
\emph{Prediction quality} (Table~\ref{tab:p2}). Both frozen pre-trained tables beat the jointly learned
random table: skip-gram \pplLSTMSkipFrozen{} and GloVe \pplLSTMGloveFrozen{} against \pplLSTMRand{} test
PPL, while the frozen random table collapses to \pplLSTMRandFrozen. Letting the pre-trained tables train
improves them further, to \pplLSTMSkipTrain{} and \pplLSTMGloveTrain, the two best language models of
this report. Seed-0/seed-1 differences in the three repeated cells are \pplSeedDiffLSTMRand, \pplSeedDiffLSTMSkipFrozen{} and \pplSeedDiffLSTMGloveFrozen{} points, so the noise floor is about one point (the three extra cells are single-seed); every contrast below is several times larger except the skip-gram/GloVe difference among trainable tables (\cSkipVsGloveTrain{} points).
\emph{Convergence} (Fig.~\ref{fig:p2}a, columns ``val ep.\ 3/6''). The ordering is visible after three epochs (GloVe-trainable \valEpThreeLSTMGloveTrain{} vs.\ random \valEpThreeLSTMRand{} vs.\ random-frozen \valEpThreeLSTMRandFrozen), and the frozen skip-gram and GloVe cells pass the random cell's final perplexity at epochs \epochReachLSTMSkipFrozen{} and \epochReachLSTMGloveFrozen; the random-frozen cell never does. \emph{Stability.} Mean pre-clip gradient norms (\gnMeanLSTMRand--\gnMeanLSTMRandFrozen) and clipped-step shares (0.3--0.4\%) are indistinguishable across cells; the only differences are isolated spikes (maximum norm \gnMaxLSTMRandSeedOne{} in one seed of the random cell, \gnMaxLSTMRandFrozen{} for the frozen random table, $\le$\gnMaxLSTMGloveTrain{} elsewhere).
\emph{Generalisation.} Frozen tables fit the training stream less but generalise relatively better:
the validation--train perplexity gap at epoch~12 is \gapLSTMGloveFrozen{} (GloVe frozen) and
\gapLSTMSkipFrozen{} (skip-gram frozen) against \gapLSTMRand{} for the random table and
\gapLSTMGloveTrain{}/\gapLSTMSkipTrain{} once the pre-trained tables train, consistent with 8.7\,M fewer
trainable parameters. \emph{Where the gain sits} (Fig.~\ref{fig:p2}b). The per-token benefit of a frozen pre-trained table is largest on rare words: on targets seen at most 10 times, frozen GloVe and skip-gram change the cross-entropy by \dRareLSTMGloveFrozen{} and \dRareLSTMSkipFrozen{} nats relative to the random table; the change shrinks with frequency and vanishes on words seen more than 10k times (\dTopLSTMGloveFrozen{} and \dTopLSTMSkipFrozen). Because rare targets are only \fracRare\% of the test set, most of the total improvement comes from words seen 11--1k times (\gainShareMidLSTMGloveFrozen\% of frozen GloVe's net gain against \gainShareRareLSTMGloveFrozen\% from the rarest bucket). Training the tables shifts the pattern: the trainable tables change less on the rarest words (GloVe \dRareLSTMGloveTrain) but are the only settings that also improve the most frequent ones (\dTopLSTMGloveTrain{} and \dTopLSTMSkipTrain), and the frozen random table loses on every bucket.
\emph{Generated text} (Appendix~A). Sampled continuations from the pre-trained cells are locally fluent WikiText (section headings, unit conversions), whereas the frozen random table degenerates into \texttt{<unk> @-@ <unk>} chains (top-$k$ distinct-2
\distinctTopkLSTMRandFrozen{} vs.\ \distinctTopkLSTMRand{} for the Part~I LSTM). Under greedy decoding
repetition is \emph{not} monotone in perplexity: the best cells loop more often
(\repGreedyLSTMGloveTrain\% of 4-grams for trainable GloVe, \repGreedyLSTMSkipFrozen\% for frozen
skip-gram) than the Part~I LSTM (\repGreedyLSTMRand\%), an observation these experiments do not explain.

\paragraph{Trainability versus extra data.}
The factorial separates the two factors the brief asks about. \emph{Trainability} (frozen vs.\ trainable at a fixed source) matters enormously when the table carries no information (\cRandFrozenVsTrain{} points) and only moderately once it does (skip-gram: \cSkipFrozenVsTrain{}; GloVe: \cGloveFrozenVsTrain). \emph{Information in the table} (random vs.\ skip-gram at fixed trainability) is worth more: \cRandVsSkipTrain{} points among trainable tables and \cRandFrozenVsSkipFrozen{} among frozen ones. The practical corollary crosses the diagonal: replacing the trainable random table by a frozen skip-gram table trained on the very same 2\,M tokens gains \cRandVsSkipFrozen{} points for \skipgramMinutes{}\,min of CPU time (under a tenth of one LM run). \emph{Extra data} (GloVe's 6\,B
tokens against our 2\,M) buys a further \cSkipVsGloveFrozen{} points frozen and \cSkipVsGloveTrain{}
trainable, i.e.\ less than having any sensible pre-trained table at all. Two caveats pull GloVe's figures in opposite directions: its most frequent missing types
(\texttt{<eos>}, \texttt{<unk>}, \texttt{@-@}) sit frozen at random vectors, a handicap, while GloVe-6B was trained on Wikipedia 2014 plus Gigaword newswire, which almost certainly contains the WikiText-2 source articles; and the
row-norm confound (rows about $6\times$ the random initialisation's norm) could explain part of its edge. Our reading, a hypothesis: with 2\,M tokens and 12 epochs the 8.7\,M-parameter input table is the slowest-learning part of the model (rare rows receive few updates, cf.\ the $n$-gram's rare-word advantage in Part~I), so giving every row a usable vector before LM training is worth more than the freedom to adjust it during training.

\paragraph{Setup.}
Each AG News \citep{zhang2015character} document (title + description, tokenised with the WikiText conventions, lowercased and mapped to the WikiText vocabulary at \agInVocab\% token
coverage, \texttt{<eos>}-prefixed, truncated at 96 tokens) becomes one 300-d vector from a frozen
model: the mean of the top-layer states over non-pad positions, or the state at the last real token;
causal models never let padding reach a real position (unit-tested). One multinomial logistic
regression on standardised features is fitted per representation, with $C$ chosen on 2,000 held-out
training documents and the 7,600-document test split never used for selection (the feature scaler and the TF-IDF vocabulary are fitted on all 20,000 unlabelled training documents at every label-set size). Embedding-only baselines (the mean of
the raw table rows) and a TF-IDF reference over the same vocabulary ids isolate what the sequence
model adds.

\paragraph{Observations.}
\emph{Pooling.} Mean pooling beats the last state for both the LSTM (\fOneLstmRandMean{} vs.\ \fOneLstmRandLast{} macro-F1) and the Transformer (\fOneTransformerRandMean{} vs.\ \fOneTransformerRandLast). \emph{Models.} With mean pooling the Part~I models rank 1-layer Transformer
(\fOneTransformerOnelRandMean) $>$ 4-layer Transformer (\fOneTransformerRandMean) $>$ RNN
(\fOneRnnRandMean) $>$ LSTM (\fOneLstmRandMean): the best language model is the worst feature extractor.
\emph{Embedding variants.} The LSTM with a frozen GloVe table gives \fOneLstmGloveFrozenMean{} and with
frozen skip-gram \fOneLstmSkipgramFrozenMean, far above the random table, but the raw tables alone do
better still (GloVe \fOneEmbGloveMean, skip-gram \fOneEmbSkipgramMean), and even the LSTM's own learned
input table (\fOneEmbRandLearnedMean) beats the LSTM's hidden states. \emph{Data size} (Fig.~\ref{fig:p3}b). TF-IDF is the best representation with \nLabelsFull{} labels (\fOneTfidf) but falls to \fOneSmallTfidf{} with \nLabelsSmall, where mean GloVe still gives \fOneSmallEmbGloveMean: dense pre-trained features dominate the low-label regime, sparse lexical features win with plentiful labels, and each LM-based representation sits below the embedding-only baseline built from its own input table at every size.
\emph{Errors} (Table~\ref{tab:p3err}, for \confusionRep). Business and Sci/Tech are confused most often (\confBusinessSciTech{} of \nTestDocs{} test documents), then World and Business (\confWorldBusiness); the most confident errors are partly label noise (sports and stock-market stories filed under \emph{World}) and partly genuine ambiguity (a Google privacy story labelled Business, predicted Sci/Tech). Vocabulary coverage does not explain errors: the \texttt{<unk>} rate is \unkRateCorrect\% in correctly and \unkRateWrong\% in wrongly classified documents.

\paragraph{Does the LM ranking agree with the downstream ranking?}
Only when the input table changes. Over all \spearmanN{} LM-based mean-pooled representations $\rho$(PPL, F1) $=\spearmanRho$ ($p=\spearmanP$; negative means lower perplexity with higher F1, i.e.\ agreement), but that agreement is carried entirely by the embedding table: across the \spearmanNArch{} architectures sharing the random table $\rho=\spearmanRhoArch$ ($p=\spearmanPArch$; descriptive at this $n$), the best LM is the worst feature extractor and the 1-layer Transformer (a worse LM) the best, whereas across the \spearmanNCells{} LSTM input-table cells $\rho=\spearmanRhoCells$: both metrics improve together, driven by the table, and the LSTM's states keep only part of what the table provides (\fOneLstmGloveFrozenMean{} vs.\ \fOneEmbGloveMean{} for the raw GloVe mean). Our explanation, a hypothesis consistent with all three parts: a next-token objective rewards local syntax and the last few words, so a well-trained recurrent state is specialised away from topic (its last state encodes what comes next, not what the document was about), whereas the Transformer's residual stream carries the input embeddings to the top layer, more faithfully with fewer layers (1 $>$ 4). Two confounds remain: the recurrent models were trained with state carried across the stream, but Part~III starts every 45-token document from a zero state, a cold start the Transformer never faces; and GloVe-6B includes Gigaword newswire, a domain match for AG News that favours the raw GloVe features. Domain shift (lowercased Wikipedia to news) hurts every LM-based representation alike; fine-tuning was outside the frozen-representation question.

\section{Conclusions, limitations and use of AI tools}
On this corpus better next-token prediction did \emph{not} give better frozen representations across architectures; across input tables both improved together, so the embedding table mattered more than the sequence model for both tasks. The LSTM is the best
full-history predictor only because it carries state beyond 128 tokens; at equal context the 4-layer
Transformer is better at 35\% more training time and half the scoring throughput. A frozen table trained on the same 2\,M tokens in \skipgramMinutes{}\,min beats jointly learned embeddings; GloVe's extra data adds \cSkipVsGloveFrozen{} points, training the pre-trained table adds \cGloveFrozenVsTrain{} more, and the per-token gains are largest on rare words. Downstream,
mean-pooled raw GloVe (\fOneEmbGloveMean) beats every LM-based feature and TF-IDF wins with enough
labels (\fOneTfidf).
\emph{Lessons learned.} Evaluate under more than one context protocol before crediting an architecture; test the input table alone before crediting the sequence model; never read representation quality off perplexity.
\emph{Limitations.} One corpus, small models and a 12-epoch budget at which nothing had converged (bounded by the 24-epoch check); MPS training is not bit-reproducible; GloVe-6B overlaps WikiText's source articles and AG News's newswire domain and its rows are longer than the other tables'; Part~III uses frozen models only; AG News carries visible label noise. \emph{Use of AI tools.} Claude Code (Anthropic, Claude Fable~5.1) \citep{claudecode2026} drafted the experiment design, the code, the scripts that generate every table and figure from the result files, and edits of this text; all experiments were run by the author and the analysis is the author's own (\texttt{AI\_USAGE.md}).
