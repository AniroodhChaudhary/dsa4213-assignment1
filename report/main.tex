\section{Question and setup}
This report tests two common assumptions about small language models (LMs) on one corpus: that lower perplexity means a better model, and that better LMs give better text representations. The question is: \emph{does better next-token prediction translate into better frozen representations for topic classification, and how much do input-embedding choices matter?} Part~I trains four LM families on WikiText-2 under one recipe; Part~II keeps the LSTM (the best full-history model of Part~I and among the cheapest per epoch) and varies only its input table in a $3\times2$ (source $\times$ trainability) design; Part~III feeds the frozen models' states to one linear classifier on AG News.

\section{Data and common protocol}
\paragraph{Corpus and vocabulary.} WikiText-2 \citep{merity2017pointer} (pre-tokenised, with its own \texttt{<unk>}) is lowercased once, one \texttt{<eos>} is appended per line, and the vocabulary is built from the train split only: \nVocab{} types. Lowercasing keeps the comparison with the uncased GloVe-6B fair; it shrinks the vocabulary from 33,278 types, so perplexities are not comparable with published numbers. Validation and test contain no out-of-vocabulary tokens beyond the dataset's own \texttt{<unk>} (\unkFracTest\% of test tokens), which every model, including the $n$-gram, treats as an ordinary vocabulary item.

\paragraph{Streams and perplexity.} Each split is one continuous token stream (train \nTrainTok{} tokens, validation \nValTok); no padding exists, so nothing has to be excluded from any loss, and every model is scored on the same \nTestTargets{} test targets, perplexity being $\exp$ of the mean per-target cross-entropy. Recurrent models are scored with batch~1 and the state carried over the entire stream (full history); the Transformer with a sliding 128-token window moved by 32, scoring the last 32 targets of each window (the first window scores all 128; every later target sees $\ge$96 tokens of context). A second protocol, non-overlapping 128-token blocks with the state reset, is identical for every model; it matches the Transformer's training condition but is a cold start for the recurrent models (trained with the state carried), so their drop under it is an upper bound on the value of context beyond 128 tokens. Validation during training uses the same protocols.

\paragraph{Models and recipe.} All neural models share a $300$-d input embedding (the largest width GloVe-6B ships, so Part~II can reuse it) initialised $\mathcal{U}(-0.1,0.1)$ and a $300\!\times\!V$ output layer, so they differ only in the sequence core: a 2-layer tanh RNN (0.36\,M core parameters), a 2-layer LSTM \citep{hochreiter1997long} (1.44\,M), a 4-layer pre-LN Transformer \citep{vaswani2017attention} with 6 heads and FFN width 1200 (4.37\,M) and, as a parameter-count control, the same Transformer with 1 layer (\coreMTransformerOne\,M). The $n$-gram baseline is interpolated Kneser--Ney \citep{kneser1995improved,chen1998empirical} with one discount per order, orders 2--5 fitted and the order chosen on validation. The neural recipe is identical for every run (hyper-parameters in Appendix~C): batch 32 $\times$ 128-token BPTT chunks with the state detached between chunks, dropout 0.3 (the Transformer additionally drops attention and FFN activations at 0.3), Adam ($10^{-3}$, 200-step warm-up), learning rate halved after two consecutive epochs without validation improvement, early stopping after three, at most 12 epochs, global gradient clipping at 1.0 with the pre-clip norm logged at every step. Unit tests check causality (future tokens cannot change earlier logits) and that input and output tables are untied.

\paragraph{Cost measurement and generation.} All runs use one Apple M4 (16\,GB) through PyTorch~2.14's MPS backend \citep{paszke2019pytorch}, one process at a time; timers synchronise the device, and epoch~1 (shader compilation) is excluded from per-epoch averages. Model size is the parameter count and the fp32 checkpoint. The common inference workload is (A)~scoring the test stream in non-overlapping 128-token blocks, 16 per batch, with each model's own protocol reported alongside, and (B)~generating 50 tokens for each of 5 prompts at batch~1 with top-$k$ sampling (Transformer without KV cache). MPS is not bit-deterministic: the 24-epoch runs repeat the first 12 epochs of the seed-0 runs and agree at epoch 12 within \mpsRepeatDiffLSTM{} (LSTM; up to \mpsRepeatMaxDiffLSTM{} PPL at intermediate epochs) and \mpsRepeatDiffTransformer{} at every epoch (Transformer); Part~II's seed-1 repeats measure seed variance (about one point); \texttt{--device cpu} reproduces exactly. Prompts are the first 10 tokens of five seeded-random \emph{validation} lines ($\ge$30 tokens, not headings, no \texttt{<unk>}); every model continues each for 50 tokens with greedy decoding and with top-$k$=40, $T$=1 sampling from one shared CPU sampler, so decoding is matched exactly across the $n$-gram and neural models; continuations are summarised by distinct-$n$ ratios and the fraction of 4-grams repeating an earlier 4-gram of the same continuation.

\paragraph{Observations.}
\emph{(a) Prediction quality} (Table~\ref{tab:p1q}). With full history the order is LSTM (\pplLSTM) $<$
Transformer (\pplTransformer) $<$ RNN (\pplRNN) $\approx$ 1-layer Transformer (\pplTransformerOne) $<$
KN 5-gram (\pplNgram). Under the matched protocol (context reset every 128 tokens for every model, the common evaluation setup) the order of the two best models \emph{reverses}: the Transformer loses only \deltaBlocksTransformer{} points, the LSTM loses \deltaBlocksLSTM{} and ends up behind it. \emph{Where the differences sit} (Fig.~\ref{fig:p1buckets}). On the \fracRare\% of test targets seen at most 10 times in training the $n$-gram is the best model (\ceRareNgram{} nats vs.\ \ceRareLSTM{} for the LSTM); every neural model wins on words seen $\ge$11 times, up to the most frequent bucket (\textgreater10k: LSTM \ceTopLSTM{} vs.\ $n$-gram \ceTopNgram). The Transformer is the best model on \texttt{<eos>} (\ceEosTransformer{} vs.\ \ceEosLSTM) but worse than the LSTM and even the $n$-gram on \texttt{<unk>} (\ceUnkTransformer{} vs.\ \ceUnkLSTM{} and \ceUnkNgram).

\emph{(b) Cost} (Table~\ref{tab:p1c}). The 4-layer Transformer needs \trainMinTransformer{}\,min of training
against \trainMinLSTM{} for the LSTM and reaches a worse full-history perplexity with 3$\times$ the core
parameters. On the common inference workload (Table~\ref{tab:p1c}) the LSTM is the fastest neural scorer; under their own batch-1 protocols the recurrent models lose 2--7$\times$ in throughput and the sliding window halves the Transformer's. Sampling costs \genMsLSTM{} (LSTM) vs.\ \genMsTransformer{}\,ms per token (Transformer, no KV cache). The $n$-gram fits all four orders in \ngramSelectSec{}\,s and scores at \scoreTokSNgram{} tokens/s on the CPU, but in this dictionary implementation its 156\,MB of tables exceed any checkpoint and sampling costs \genMsNgram{}\,ms per token.

\emph{(c) Learning behaviour} (Fig.~\ref{fig:p1curves}). All four neural models were still improving at the 12-epoch cap: no learning-rate halving or early stop fired, and the train/validation gap grows (LSTM: \trainPplLastLSTM{} with dropout on vs.\ \valPplLastLSTM{} at epoch 12) without the validation loss turning up, i.e.\ no overfitting at this budget. Per epoch the LSTM and 4-layer Transformer track each other; per wall-clock minute the LSTM leads the Transformer. After three epochs the tanh RNN is the \emph{best} model (\valEpThreeRNN{} vs.\ \valEpThreeLSTM{} and \valEpThreeTransformer); it learns fastest and saturates first.

\emph{(d) Generated text} (all continuations in Appendix~A, repetition statistics in Table~\ref{tab:p1rep}). Under greedy decoding the RNN and 1-layer Transformer loop (\repGreedyRNN\% and \repGreedyTransformerOne\% of 4-grams repeat an earlier one; $n$-gram \repGreedyNgram\%), the LSTM and 4-layer Transformer far less (\repGreedyLSTM\%, \repGreedyTransformer\%). Top-$k$ sampling removes repetition for every model ($\le$\repTopkTransformerOne\%), so sampled continuations differ in local fluency and consistency instead: the Transformer holds a topic across the 50 tokens (a ``route description'' heading after the highway prompt, a Jin/Song court after the 1644 prompt), the LSTM holds a looser one (military and geographic vocabulary after prompts 1 and 4), the RNN drifts within a sentence and the $n$-gram within a few tokens.

\paragraph{Explanations, separated from the observations.}
\emph{The LSTM's lead is consistent with a context-length effect.} Under context reset the Transformer is the better predictor, so the LSTM's full-history lead is attributable (up to the cold-start caveat of \S2) to information carried beyond 128 tokens (WikiText articles are thousands of tokens long); whether a longer-window Transformer would close the gap was not tested, and carrying state indefinitely is itself an architectural property. \emph{Parameter count does not explain the ranking.} The 1-layer Transformer has about the
LSTM's core size (\coreMTransformerOne{}M vs.\ \coreMLSTM{}M) and is \deltaOneLayerVsLSTM{} points
worse, while the 4-layer model has 3$\times$ the LSTM's core and is still worse with full history, so parameter count does not explain the ranking.
\emph{Training budget conditions every conclusion.} Nothing converged in 12 epochs and the ranking at epoch~3 (RNN first) differs from that at epoch~12, so we re-ran the LSTM and Transformer for 24 epochs (Table~\ref{tab:p1q}, dashed in Fig.~\ref{fig:p1curves}): the LSTM early-stopped (best at epoch \bestEpochLongLSTM, test PPL \pplLongLSTM), the Transformer was still improving at epoch 24 (\pplLongTransformer), and under context reset the Transformer still leads (\pplLongBlocksTransformer{} vs.\ \pplLongBlocksLSTM), so both conclusions survive a doubled budget. \emph{The $n$-gram's edge on rare words} is
expected from Kneser--Ney's continuation counts, which model how many contexts a rare type appears in,
whereas a row whose word occurs at most ten times per epoch receives few informative gradient signals
(a hypothesis; Part~II tests its input side with pre-trained rows, while the equally under-trained output rows stay untested). \emph{The RNN's slow batch-1 scoring} is most likely a kernel effect rather than an architectural one (batched in 128-token blocks it reaches \scoreBlocksTokSRNN{} tokens/s, still below the LSTM), a hypothesis not tested on other hardware. \emph{Greedy loops} track model quality among the four neural Part~I models (\repGreedyRNN\% and \repGreedyTransformerOne\% vs.\ \repGreedyLSTM\% and \repGreedyTransformer\%) under one identical decoder, so there they reflect weaker modelling of the recent context rather than the decoding rule; the $n$-gram (\repGreedyNgram\%) and the Part~II cells (\S4) show the relation is not monotone in perplexity.

\paragraph{Design.}
The LSTM of Part~I is retrained with its $300$-d input table replaced by (b) skip-gram vectors \citep{mikolov2013distributed} trained
by us on the WikiText-2 train stream only (gensim \citep{rehurek2010gensim}, negative sampling; \skipgramMinutes{}\,min on the CPU,
reported separately from LM training) and (c) public GloVe-6B vectors \citep{pennington2014glove}, both
kept entirely frozen; (a) is the Part~I model itself. Because the required three cells confound \emph{trainability} with \emph{information content}, three extra cells complete a $3\times2$ factorial: the two pre-trained tables left trainable, and a frozen random table (no information at all). Skip-gram covers every type in the stream (\texttt{min\_count}=1). GloVe covers \gloveCoverageTypes\% of the types and \gloveCoverageTokens\% of train tokens; the \gloveMissing{} missing types include the most frequent tokens of all (\texttt{<eos>}, \texttt{<unk>}, \texttt{@-@}) and are initialised $\mathcal{N}(0,\sigma_d)$ with $\sigma_d$ the per-dimension standard deviation of the found rows. The tables differ in scale (mean row norm \rowNormGloveTable{} GloVe, \rowNormSkipgramTable{} skip-gram, 1.0 random), which a control run below tests. Freezing is verified by hashing the table before and after training; the required cells are run with seeds 0 and 1.

\paragraph{Observations.}
\emph{Prediction quality} (Table~\ref{tab:p2}). Both frozen pre-trained tables beat the jointly learned
random table: skip-gram \pplLSTMSkipFrozen{} and GloVe \pplLSTMGloveFrozen{} against \pplLSTMRand{} test
PPL, while the frozen random table collapses to \pplLSTMRandFrozen. Letting the pre-trained tables train
improves them further, to \pplLSTMSkipTrain{} and \pplLSTMGloveTrain, the two best LMs here. Seed differences in the three repeated cells are \pplSeedDiffLSTMRand, \pplSeedDiffLSTMSkipFrozen{} and \pplSeedDiffLSTMGloveFrozen{} points (noise floor about one point; the extra cells are single-seed); every contrast below is several times larger except skip-gram vs.\ GloVe among trainable tables (\cSkipVsGloveTrain{} points).

\emph{Convergence} (Fig.~\ref{fig:p2}a, columns ``val ep.\ 3/6''). The ordering is visible after three epochs (Table~\ref{tab:p2}), and the frozen skip-gram and GloVe cells pass the random cell's final perplexity at epochs \epochReachLSTMSkipFrozen{} and \epochReachLSTMGloveFrozen; the random-frozen cell never does.

\emph{Stability.} Mean pre-clip gradient norms (\gnMeanLSTMRand--\gnMeanLSTMRandFrozen) and clipped-step shares (0.3--0.4\%) are indistinguishable across cells; the only differences are isolated spikes (maximum norm \gnMaxLSTMRandSeedOne{} in one seed of the random cell, \gnMaxLSTMRandFrozen{} for the frozen random table, $\le$\gnMaxLSTMGloveTrain{} elsewhere).

\emph{Generalisation.} Frozen tables fit the training stream less but generalise relatively better: validation--train gaps at epoch 12 are \gapLSTMGloveFrozen{} and \gapLSTMSkipFrozen{} (frozen GloVe, skip-gram) against \gapLSTMRand{} for the random table and \gapLSTMGloveTrain{}/\gapLSTMSkipTrain{} once the pre-trained tables train, consistent with 8.7\,M fewer trainable parameters.

\emph{Where the gain sits} (Fig.~\ref{fig:p2}b). The per-token benefit of a frozen pre-trained table is largest on rare words: on targets seen at most 10 times, frozen GloVe and skip-gram change the cross-entropy by \dRareLSTMGloveFrozen{} and \dRareLSTMSkipFrozen{} nats relative to the random table; the change shrinks with frequency and vanishes on words seen more than 10k times (\dTopLSTMGloveFrozen{} and \dTopLSTMSkipFrozen). Rare targets are only \fracRare\% of the test set, so most of the total gain comes from words seen 11--1k times (\gainShareMidLSTMGloveFrozen\% vs.\ \gainShareRareLSTMGloveFrozen\% of frozen GloVe's net gain). Trainable tables change less on the rarest words (GloVe \dRareLSTMGloveTrain) but are the only settings that also improve the most frequent ones (\dTopLSTMGloveTrain{} and \dTopLSTMSkipTrain); the frozen random table loses on every bucket.

\emph{Generated text} (Appendix~A). Sampled continuations from the pre-trained cells are locally fluent WikiText, whereas the frozen random table degenerates into \texttt{<unk>}-laden text, at worst \texttt{<unk> @-@ <unk>} chains (top-$k$ distinct-2 \distinctTopkLSTMRandFrozen{} vs.\ \distinctTopkLSTMRand). Greedy repetition is \emph{not} monotone in perplexity: the best cells loop more (\repGreedyLSTMGloveTrain\% for trainable GloVe) than the Part~I LSTM (\repGreedyLSTMRand\%), which these experiments do not explain.

\paragraph{Trainability versus extra data.}
The factorial separates the two factors the brief asks about. \emph{Trainability} (frozen vs.\ trainable at a fixed source) matters enormously when the table carries no information (\cRandFrozenVsTrain{} points) and only moderately once it does (skip-gram: \cSkipFrozenVsTrain{}; GloVe: \cGloveFrozenVsTrain). \emph{Information in the table} (random vs.\ skip-gram at fixed trainability) is worth more: \cRandVsSkipTrain{} points among trainable tables and \cRandFrozenVsSkipFrozen{} among frozen ones. Practically, a frozen skip-gram table trained on the same 2\,M tokens in \skipgramMinutes{}\,min (under a tenth of one LM run) beats the trainable random table by \cRandVsSkipFrozen{} points. \emph{Extra data} (GloVe's 6\,B tokens against our 2\,M) buys a further \cSkipVsGloveFrozen{} points frozen and \cSkipVsGloveTrain{} trainable, less than having any sensible pre-trained table. Caveats pull GloVe both ways: its most frequent missing types (\texttt{<eos>}, \texttt{<unk>}, \texttt{@-@}) sit frozen at random vectors, a handicap, while GloVe-6B's Wikipedia 2014 plus Gigaword training data almost certainly contains the WikiText-2 source articles; and the row-norm control (last row of Table~\ref{tab:p2}) shows that \emph{input scale} is a large part of the frozen-table gains: the GloVe table rescaled to the random initialisation's norm (identical directions, 0.15$\times$ the length) reaches \pplLSTMGloveFrozenScaled{} test PPL, \cGloveScaledVsGlove{} points worse than the unscaled table and no better than the trainable random table. A frozen table fixes the input scale, which a trainable table must learn (the random table's mean row norm grows only from 1.0 to 1.46 in 12 epochs), and the skip-gram table (norm 2.4) presumably benefits in the same way; downstream, where features are standardised, scale cannot matter, so Part~III's GloVe advantage is content. Our reading, a hypothesis: with 2\,M tokens and 12 epochs the 8.7\,M-parameter input table is the slowest-learning part of the model (rare rows receive few updates, and Adam's per-parameter steps grow the table's scale slowly), so giving every row a usable, well-scaled vector before LM training is worth more than the freedom to adjust it during training.

\paragraph{Setup.} Each AG News \citep{zhang2015character} document (title + description, tokenised with sacremoses \citep{koehn2007moses} to the WikiText conventions, lowercased, mapped to the WikiText vocabulary at \agInVocab\% token coverage, \texttt{<eos>}-prefixed, truncated at 96 tokens for \agTruncated\% of documents) becomes one 300-d vector from a frozen model: the mean of the top-layer states over non-pad positions, or the state at the last real token; causal models never let padding reach a real position (unit-tested). One multinomial logistic regression \citep{pedregosa2011scikit} on standardised features is fitted per representation, $C$ chosen on the same 2,000 held-out training documents at every label-set size, the 7,600-document test split never used for selection (scaler and TF-IDF vocabulary are fitted on all 20,000 unlabelled training documents). Embedding-only baselines (the mean of the raw table rows) and a TF-IDF reference over the same vocabulary ids isolate what the sequence model adds.

\paragraph{Observations.}
\emph{Pooling.} Mean pooling beats the last state for both the LSTM (\fOneLstmRandMean{} vs.\ \fOneLstmRandLast{} macro-F1) and the Transformer (\fOneTransformerRandMean{} vs.\ \fOneTransformerRandLast).

\emph{Models.} With mean pooling the Part~I models rank 1-layer Transformer (\fOneTransformerOnelRandMean) $>$ 4-layer Transformer (\fOneTransformerRandMean) $>$ RNN (\fOneRnnRandMean) $>$ LSTM (\fOneLstmRandMean); 95\% bootstrap intervals over the test documents are $\pm$\ciHalfMin--\ciHalfMax{} points and every gap quoted here is separable (1L$-$4L: \pdTransformerOnelRandMeanVsTransformerRandMean), with the caveat of one LM seed per model. The best language model is the worst feature extractor.

\emph{Embedding variants.} The LSTM with a frozen GloVe table gives \fOneLstmGloveFrozenMean{} and with
frozen skip-gram \fOneLstmSkipgramFrozenMean, far above the random table, but the raw tables alone do
better still (GloVe \fOneEmbGloveMean, skip-gram \fOneEmbSkipgramMean), and even the LSTM's own learned
input table (\fOneEmbRandLearnedMean) beats the LSTM's hidden states.

\emph{Data size} (Fig.~\ref{fig:p3}b). TF-IDF is the best representation with \nLabelsFull{} labels (\fOneTfidf) but falls to \fOneSmallTfidf{} with \nLabelsSmall, where mean GloVe still gives \fOneSmallEmbGloveMean: dense pre-trained features dominate the low-label regime, sparse lexical features win with plentiful labels, and every LM-based representation sits below the embedding-only baseline built from its own input table \ownTableSizes{} (at 20,000 labels the states lose \ownLossTransformerOnelRandMean{}--\ownLossLstmRandMean{} points relative to their own tables).

\emph{Errors} (Table~\ref{tab:p3err}, for \confusionRep). Business and Sci/Tech are confused most often (\confBusinessSciTech{} of \nTestDocs{} test documents), then World and Business (\confWorldBusiness); the most confident errors are partly label noise (sports and stock-market stories filed under \emph{World}) and partly genuine ambiguity (a Google privacy story labelled Business, predicted Sci/Tech). Vocabulary coverage does not explain errors: the \texttt{<unk>} rate is \unkRateCorrect\% in correctly and \unkRateWrong\% in wrongly classified documents.

\paragraph{Does the LM ranking agree with the downstream ranking?}
Only when the input table changes. Over all \spearmanN{} LM-based mean-pooled representations $\rho$(PPL, F1) $=\spearmanRho$ ($p=\spearmanP$; negative = agreement), but that agreement is carried entirely by the embedding table: across the \spearmanNArch{} architectures sharing the random table $\rho=\spearmanRhoArch$ ($p=\spearmanPArch$; descriptive at this $n$), the best LM is the worst feature extractor and the 1-layer Transformer (a worse LM) the best, whereas across the \spearmanNCells{} LSTM input-table cells $\rho=\spearmanRhoCells$: both metrics improve together, driven by the table, and the LSTM's states keep only part of what the table provides (\fOneLstmGloveFrozenMean{} vs.\ \fOneEmbGloveMean{} for the raw GloVe mean). Our explanation, a hypothesis consistent with all three parts: a next-token objective rewards local syntax and the last few words, so sequence-model states are specialised away from topic; every model's mean-pooled states score \emph{below} its own input table, by least for the Transformers (\ownLossTransformerOnelRandMean{} and \ownLossTransformerRandMean{} points, whose residual stream carries the embeddings to the top layer) and most for the LSTM (\ownLossLstmRandMean), whose gates overwrite them. Two confounds remain: recurrent models were trained with state carried across the stream but Part~III starts every 45-token document from a zero state, a cold start the Transformer never faces; and GloVe-6B's Gigaword newswire is a domain match for AG News that favours the raw GloVe features. Domain shift presumably hurts every LM-based representation, which we did not test; fine-tuning was outside the frozen-representation question.

\section{Conclusions, limitations and use of AI tools}
Across architectures, better next-token prediction did \emph{not} give better frozen representations; across input tables both improved together, so the embedding table mattered more than the sequence model for the downstream task (for perplexity, architecture still dominated among usable tables). The LSTM is the best
full-history predictor because it carries state beyond 128 tokens; at equal context the 4-layer Transformer is better, at \trainTimePct\% more training time and \blocksThroughputPct\% of the LSTM's throughput on the common workload. A frozen table trained on the same 2\,M tokens in \skipgramMinutes{}\,min beats jointly learned embeddings; GloVe's extra data adds \cSkipVsGloveFrozen{} points, training the pre-trained table adds \cGloveFrozenVsTrain{} more, the per-token gains are largest on rare words, and a rescaling control shows that the frozen GloVe table's gain over the trainable random table is input scale rather than content (among frozen tables, content still dominates). Downstream,
mean-pooled raw GloVe (\fOneEmbGloveMean) beats every LM-based feature and TF-IDF wins with enough
labels (\fOneTfidf).
\emph{Failure cases.} Greedy decoding degenerates into heading loops for every model (\repGreedyRNN\% repeated 4-grams for the RNN); the frozen random table emits \texttt{<unk>} chains; the LSTM's last state is the worst representation (\fOneLstmRandLast); the best Part~II cells loop more under greedy decoding, unexplained. \emph{Lessons learned.} Evaluate under more than one context protocol before crediting an architecture; test the input table alone, and its scale, before crediting the sequence model; never read representation quality off perplexity.
\emph{Limitations.} One corpus, small models, a 12-epoch budget at which nothing converged; MPS is not bit-reproducible; GloVe-6B overlaps WikiText's sources and AG News's domain; Part~III uses frozen models only; AG News has label noise. \emph{Code and tools.} Code, configurations and results: \url{https://github.com/AniroodhChaudhary/dsa4213-assignment1}. The training loop follows PyTorch's \texttt{word\_language\_model} example; data via Hugging Face \texttt{datasets}. Claude Code (Anthropic, Claude Fable~5.1) \citep{claudecode2026} drafted the design, code, asset scripts and text edits; the author ran all experiments and owns the analysis (\texttt{AI\_USAGE.md}).
